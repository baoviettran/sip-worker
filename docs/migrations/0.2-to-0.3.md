# Migrating from sip-worker 0.2.0 to 0.3.0

This is a **clean package-boundary release**: 0.3.0 splits the single 0.2.0
package into three npm workspaces. There is no compatibility export and no
package-level deprecation shim — old import paths that no longer exist fail
with a clean resolution error so you notice and update them.

- browser entry point: **`sip-worker`**
- environment-neutral protocol core: **`@sip-worker/core`**
- Node transports and native liveness: **`@sip-worker/node`**

0.3.0 remains a **signaling-only** release, pre-1.0. It does **not** add WebRTC,
browser reconnection policy, or a production-readiness claim.

## Install

For browser use, install the browser root package:

```bash
npm install sip-worker
```

For Node use, install the core and Node packages:

```bash
npm install @sip-worker/core @sip-worker/node
```

Both `sip-worker` and `@sip-worker/node` depend on `@sip-worker/core@0.3.0`
exactly, so npm installs a single shared copy of the core.

## Import mapping

The following table is the exact old-to-new mapping for 0.3.0. Every moved or
removed 0.2 import is listed here.

| Before 0.3.0 | 0.3.0 |
|---|---|
| `sip-worker` for `UserAgent`, errors, and common browser API | `sip-worker` |
| `sip-worker/messages` | `@sip-worker/core/messages` |
| `sip-worker/stream` | `@sip-worker/core/stream` |
| `sip-worker/transactions` | `@sip-worker/core/transactions` |
| `sip-worker/dialogs` | `@sip-worker/core/dialogs` |
| `sip-worker/auth` | `@sip-worker/core/auth` |
| `sip-worker/ua` | `@sip-worker/core/ua` or browser root `sip-worker` |
| `sip-worker/media` | `@sip-worker/core/media` |
| `sip-worker/bridge` | `@sip-worker/core/bridge` |
| browser part of `sip-worker/reliability` | `@sip-worker/core/reliability` |
| `sip-worker/transport/browser` | `sip-worker/transport` |
| `sip-worker/transport/node` | `@sip-worker/node/transport` |
| Node liveness from `sip-worker/reliability` | `@sip-worker/node/reliability` |

## Removed path

`sip-worker/transport/node` is **removed**. There is no compatibility export and
no package-level deprecation shim. If you imported it directly, import the Node
transports from `@sip-worker/node` (root or `@sip-worker/node/transport`):

```js
// 0.2
import { NodeWebSocketTransport } from 'sip-worker/transport/node';
// 0.3
import { NodeWebSocketTransport } from '@sip-worker/node/transport';
```

## Browser root re-exports common core API

The browser root `sip-worker` is a direct re-export of the common core API, so
the `UserAgent`, errors, and the browser-safe signaling flow keep working from
the root exactly as in 0.2. Low-level protocol modules (messages, transactions,
dialogs, auth, streams, media, bridge) now live in `@sip-worker/core`; import
them from there when you need them directly.

## Equivalent imports

### ESM

```js
// Browser — root + browser transport
import { UserAgent, AuthManager } from 'sip-worker';
import { BrowserWebSocketTransport } from 'sip-worker/transport';

// Node — root + Node transports + native liveness
import { UserAgent, AuthManager } from '@sip-worker/core';
import { NodeUdpTransport, NodeWebSocketTransport } from '@sip-worker/node';
import { NodeWebSocketLiveness } from '@sip-worker/node/reliability';

// Low-level protocol modules
import { SipRequestMessage } from '@sip-worker/core/messages';
import { SipStreamDecoder } from '@sip-worker/core/stream';
import { SipIngress } from '@sip-worker/core/transport';
import { ClientTransaction } from '@sip-worker/core/transactions';
import { Dialog } from '@sip-worker/core/dialogs';
```

### CommonJS

```js
const { UserAgent, AuthManager } = require('sip-worker');
const { BrowserWebSocketTransport } = require('sip-worker/transport');

const core = require('@sip-worker/core');
const { NodeUdpTransport, NodeWebSocketTransport } = require('@sip-worker/node');
const { NodeWebSocketLiveness } = require('@sip-worker/node/reliability');
const messages = require('@sip-worker/core/messages');
```

### TypeScript

Strict types are shipped per package and per subpath, so the imports above are
fully typed. Example:

```ts
import { UserAgent, AuthManager } from '@sip-worker/core';
import { NodeWebSocketTransport } from '@sip-worker/node/transport';
import type { Clock } from '@sip-worker/core/transport';

const clock: Clock = { now: Date.nowProxy, setTimeout, clearTimeout };
const ua = new UserAgent({
  transport: new NodeWebSocketTransport(ws),
  clock,
  registrarUri: 'sip:registrar.example.com',
  aor: 'sip:alice@example.com',
  contact: '<sip:alice@192.0.2.1:5060>',
  credentials: { username: 'alice', password: 'your-password' },
  idGenerator: { branch: () => crypto.randomUUID() },
  authManager: new AuthManager({ branch: () => crypto.randomUUID() }),
});
```

The browser example is the same but imports `UserAgent` from `sip-worker` and
`BrowserWebSocketTransport` from `sip-worker/transport`.

## What this release is not

0.3.0 is a package-boundary release only. It does **not** add WebRTC, does not
introduce a browser reconnection or network-change policy, and makes no
production-ready-for-general-deployment claim. It is still a signaling-only
prototype, pre-1.0. See
[SECURITY.md](../../SECURITY.md) and the
[browser v1.0 production roadmap](../superpowers/specs/2026-08-12-browser-v1-production-roadmap-design.md)
for the exact limits.
