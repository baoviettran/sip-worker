# Migrating from sip-worker 0.3.0 to 0.5.0

The 0.3 → 0.5 step adds **real browser WebRTC media** to the `sip-worker`
(browser) package and the core media controller. It is still pre-1.0. There is
**no compatibility shim**: the breaking changes below fail loudly so you update
them.

- browser entry point: **`sip-worker`** (now adds real WebRTC media)
- environment-neutral protocol core: **`@sip-worker/core`**
- Node transports and native liveness: **`@sip-worker/node`**

All three packages move together from `0.3.0` to **`0.5.0`**.

## Breaking change: `Invitation.answer(localSdp)` → `answer()`

The single most important change. In 0.3, an incoming call offered SDP to the
application and you answered with the local SDP explicitly:

```ts
// 0.3
ua.on('incomingCall', async ({ invitation }) => {
  const localSdp = await invitation.answer('...'); // passed a local SDP string
});
```

In 0.5, the core invitation drives the media controller itself: it applies the
**remote** offer and creates the **local** answer internally, then sends
`200 OK` with that SDP. The argument is gone:

```ts
// 0.5
ua.on('incomingCall', async ({ invitation }) => {
  await invitation.answer(); // no argument; media layer negotiates
});
```

This is an intentional pre-1.0 breaking API change. Remove the argument.

## New: `BrowserUserAgent` and `ua.media`

The browser root `sip-worker` now exports `BrowserUserAgent`, the composition
root that wires core SIP to the browser media layer, and exposes `ua.media`:

```ts
import { BrowserUserAgent, BrowserWebSocketTransport } from 'sip-worker';

const ua = new BrowserUserAgent({
  transport: new BrowserWebSocketTransport('wss://sip.example.com/ws'),
  clock, registrarUri, aor, contact, idGenerator,
  media: { /* BrowserMediaOptions */ },
});

await ua.media.prepare();
await ua.connect();
await ua.register();
await ua.invite('sip:bob@example.com');
// ...
await ua.dispose();
```

The `media.facade` surface is:

```ts
listDevices();
prepare(options?);                    // accepts an AbortSignal
selectMicrophone(deviceId | undefined);
attachRemoteAudio(element, options?); // returns an idempotent detach
setAudioOutput(element, deviceId);
```

`BrowserUserAgent` also re-exposes `restartIce()`, the SIP methods
(`connect`/`register`/`unregister`/`invite`/`bye`/`dispose`), and the core SIP
getters (`registerState`, `identity`, `callState`). Its typed event surface is
the union of the core events and the four media events (`mediaStateChanged`,
`remoteAudio`, `mediaFailed`, `deviceChanged`).

The core `UserAgent` still works for signaling-only composition; `BrowserUserAgent`
is the production root for a real-media browser call.

## New: coded media errors

Media failures are now `MediaError` with a 12-value `MediaErrorCode` (`code`)
instead of a bare/stubbed error. Map every code before surfacing UI; the full
table is in [`docs/media-errors.md`](../../docs/media-errors.md). Note that
`INVALID_STATE` is **not** in the media union and is mapped to `INTERNAL_ERROR`
at the bridge.

## What did not move

The 0.3 package boundaries are unchanged: `sip-worker` depends on
`@sip-worker/core@0.5.0` exactly; `@sip-worker/node` depends on
`@sip-worker/core@0.5.0` exactly; core has no dependencies. The low-level import
map from [`0.2-to-0.3.md`](./0.2-to-0.3.md) still holds for `0.3.0 → 0.5.0`,
except the browser root `sip-worker` now additionally carries the browser media
surface described above.

The migration from 0.2 → 0.3 (`docs/migrations/0.2-to-0.3.md`) still applies for
all of `@sip-worker/core`/`/node` subpath moves; nothing reverted.

## Behavior notes

- **One-call rule.** `BrowserUserAgent` supports one active media call. A second
  incoming INVITE while busy is answered **486 Busy Here** at the SIP level
  before any media is acquired.
- **ICE restart.** `restartIce()` is valid only on the sole confirmed active
  call; otherwise it rejects with `INVALID_STATE`.
- v0.5 is a **real-media foundation**, not a completed v1 production product.
  Inbound SDP is no longer exposed to the application; the media layer owns
  offer/answer. See the [browser v1.0 roadmap](../../docs/superpowers/specs/2026-08-12-browser-v1-production-roadmap-design.md)
  and [`docs/browser-media.md`](../../docs/browser-media.md) for the shipped
  surface and its exact limitations.

## Equivalent imports

### ESM

```js
// Browser — composition root + browser transport
import { BrowserUserAgent, BrowserWebSocketTransport } from 'sip-worker';

// Core signaling, low-level protocol (unchanged from 0.3)
import { UserAgent, AuthManager } from '@sip-worker/core';
import { NodeUdpTransport, NodeWebSocketTransport } from '@sip-worker/node';
import { MediaError } from '@sip-worker/core/media';
```

### CommonJS

```js
const { BrowserUserAgent, BrowserWebSocketTransport } = require('sip-worker');
const { NodeUdpTransport } = require('@sip-worker/node');
```

### TypeScript

```ts
import { BrowserUserAgent } from 'sip-worker';
import type { BrowserUserAgentOptions, BrowserUserAgentEventMap } from 'sip-worker';

const opts: BrowserUserAgentOptions = { /* transport, clock, registrarUri, ... */ };
const ua = new BrowserUserAgent(opts);
ua.on('mediaFailed', ({ error }) => console.log(error.code));
await ua.media.prepare();
await ua.dispose();
```

## What this release is not

0.5.0 adds a real WebRTC audio foundation but is not a completed v1 product: one
call at a time, non-trickle ICE only, no DTMF/SIP INFO/MSRP, no auto-device
fallback, no SIPS, and no interop evidence against production media stacks. See
[SECURITY.md](../../SECURITY.md) and
[`docs/browser-media.md`](../../docs/browser-media.md) for the exact limits.
