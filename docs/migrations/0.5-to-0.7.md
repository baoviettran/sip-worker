# Migrating from sip-worker 0.5.0 to 0.7.0

The 0.5 → 0.7 step replaces the v0.5 `BrowserUserAgent` + `ua.media`
composition with a **product composition root** (`BrowserPhone`), **per-call
ownership** (`BrowserCall`/`OutgoingBrowserCall`/`IncomingBrowserCall`), and
**bounded recovery** plus **call controls** (mute, hold/resume, RFC 4733 DTMF)
over the real WebRTC audio foundation. It is still pre-1.0. There is **no
compatibility shim**: the breaking changes below fail loudly so you update
them.

- browser entry point: **`sip-worker`** (now adds call controls and recovery)
- environment-neutral protocol core: **`@sip-worker/core`**
- Node transports and native liveness: **`@sip-worker/node`**

All three packages move together from `0.5.0` to **`0.7.0`**, and the adapter
dependency pins are exact: `sip-worker@0.7.0 → @sip-worker/core@0.7.0`,
`@sip-worker/node@0.7.0 → @sip-worker/core@0.7.0`; core has no dependencies.

## New: `BrowserPhone` and per-call ownership

The v0.5 pattern drove a single user agent with a media facade and
one-shot `invite()`:

```ts
// 0.5
const ua = new BrowserUserAgent({ transport, clock, registrarUri, aor, contact, idGenerator, media });
await ua.connect();
await ua.register();
await ua.invite('sip:bob@example.com'); // settles on core confirm
await ua.bye();
await ua.dispose();
```

In 0.7 the phone owns the transport/registration/media environment, and the
call is an explicit first-class handle you construct before dialing:

```ts
// 0.7
const phone = new BrowserPhone({ options, factory, lifecycle, mediaEnvironment });
await phone.connect();
await phone.register();
const call = phone.createCall('sip:bob@example.com') as OutgoingBrowserCall;
await call.start(); // settles on confirm AND media connected
await call.hangup();
await phone.unregister();
await phone.dispose();
```

## Signature map

The v0.5 → v0.7 signature changes on the browser surface:

| 0.5.0 | 0.7.0 |
| --- | --- |
| `new BrowserUserAgent({ transport, clock, ... })` | `new BrowserPhone({ options, factory, lifecycle, mediaEnvironment })` |
| `ua.connect()` / `ua.register()` / `ua.unregister()` | `phone.connect()` / `phone.register()` / `phone.unregister()` |
| `ua.invite(target)` | `phone.createCall(target).start()` |
| `ua.bye()` | the active call's `hangup()` |
| `ua.restartIce()` | the active call's `restartIce()` |
| `ua.media` facade (prepare/listDevices/selectMicrophone/attachRemoteAudio/setAudioOutput) | app-owned `getUserMedia` + `remoteAudio` stream events; media options on the phone |
| `ua.on('incomingCall', ({ invitation }) => invitation.answer())` | `phone.on('incomingCall', ({ call }) => call.answer())` |

The v0.5 `BrowserUserAgent` remains importable and functional as a
**deprecated compatibility wrapper** over the same owners — it delegates to the
same phone runtime and creates no second reconnect/call/media state machine.
Its `invite()` settles on core confirm only (not media) and rejects (never
throws) on a second simultaneous invite.

## Breaking change: `Registrar.onTransportConnected()` removed

The core `Registrar` class no longer exposes `onTransportConnected()`. In 0.7
the user agent owns transport-connect recovery internally (registration is
restored through the awaitable registration-recovery path); only
`onTransportDisconnected()` remains on `Registrar`. Code that called
`registrar.onTransportConnected()` must drop the call — the transport-connected
recovery hook is now internal. `Registrar.register()` returns a promise that
settles when the registration is committed.

## New state, error, and recovery surface

- **State unions.** `ConnectionState`, `RegistrationState`, `CallState`,
  `CallSignalingState`, and `HoldState` are public and documented in
  [docs/browser-phone.md](../browser-phone.md).
- **New error codes.** `CONNECTION_RECOVERY_EXHAUSTED`,
  `REGISTRATION_RECOVERY_FAILED`, `SIGNALING_RECOVERY_FAILED`,
  `OPERATION_ABORTED`, `OPERATION_TIMEOUT`, `OPERATION_IN_PROGRESS`,
  `HOLD_NEGOTIATION_FAILED`, `DTMF_UNSUPPORTED`, `DTMF_FAILED`.
- **Reconnect policy.** Defaults 250 ms initial delay, 5 s max delay, 8
  attempts, 30 s recovery budget; caps 20 attempts, 30 s delay, 120 s recovery.
- **Diagnostics.** `phone.diagnostics.resources()` plus the closed
  `DiagnosticCode` union — see [docs/diagnostics.md](../diagnostics.md).
- **TURN provider.** `iceServerProvider` serves refreshed short-lived
  credentials; the credentials object is validated and the phone adopts the
  new pair on refresh.

## Reference softphone

The repository's reference softphone
(`examples/browser-softphone`) is the packed-artifact consumer to copy. It
demonstrates the full v0.7 lifecycle, controls, and diagnostics against the
exact packed `sip-worker@0.7.0` tarball and is referenced from the root
README.

## Update your calls

The clean-break list, in one pass:

1. Replace `new BrowserUserAgent(...)` with `new BrowserPhone({ options, factory, lifecycle, mediaEnvironment })` and move your media options into `options.media`.
2. Replace `ua.invite(target)` with `const call = phone.createCall(target) as OutgoingBrowserCall; await call.start();`.
3. Replace `ua.bye()` with `await call.hangup()`.
4. Replace `ua.restartIce()` with `await call.restartIce()`.
5. Move remote-audio playback from `ua.media.attachRemoteAudio(element, ...)` to the `remoteAudio` stream event on the call.
6. Remove any direct `registrar.onTransportConnected()` calls.
7. Update your error handling to the v0.7 codes above; media errors keep the
   v0.5 `MediaError` codes.
