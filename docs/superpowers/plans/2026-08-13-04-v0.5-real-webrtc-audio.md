# v0.5 Real Browser WebRTC Audio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the 0.5.0 media foundation: real incoming and outgoing browser audio, bounded non-trickle ICE, microphone/output management, explicit ICE restart, typed failures, leak-free ownership, and reproducible browser/TURN/Safari evidence.

**Architecture:** `BrowserUserAgent` composes the environment-neutral core `UserAgent`, a `WorkerMediaController`, and a browser `WebRtcMediaManager` connected through the structured media protocol. Each call owns one `WebRtcMediaSession`, peer connection, microphone track, and remote stream; core owns SIP offer/answer and re-INVITE sequencing but never imports browser APIs.

**Tech Stack:** TypeScript 5 strict `NodeNext`, Vitest 2, npm workspaces, WebRTC browser APIs, Playwright Test 1.62.0 (Chromium/Firefox/WebKit), pinned coturn, GitHub Actions Linux/macOS, API Extractor, tsup, esbuild.

## Global Constraints

- Implement the approved [v0.5 design](../specs/2026-08-13-v0.5-real-webrtc-audio-design.md) exactly.
- Work in a dedicated worktree created with `using-git-worktrees`; do not implement on `main`.
- Begin from commit `61814983ec9f55d71a66f17feeee9cfad1f33979` or a reviewed descendant.
- Do not alter, delete, stage, or commit host-managed `.claude/`.
- Use TDD: one focused failing assertion, confirm the expected failure, minimal implementation, focused green run.
- Versions are synchronized at `0.5.0`; adapters depend exactly on `@sip-worker/core: "0.5.0"`.
- Core remains free of DOM, WebRTC, Node, ambient timers, and import-time global access.
- Browser code never imports Node or reads `navigator`, `document`, or `RTCPeerConnection` at module evaluation.
- One `BrowserUserAgent` supports one active/negotiating media call.
- One call owns one peer connection, one audio `sendrecv` transceiver, and one fresh microphone track.
- Initial offer/answer and restart use complete non-trickle SDP after bounded ICE gathering.
- Prefer Opus, retain PCMU/PCMA and related telephone-event entries, use `setCodecPreferences()` when available, and never munge SDP text.
- Never log SDP, candidates/IPs, constraints, device identifiers/labels, SIP credentials, or TURN credentials.
- Termination/disposal wins every race and reclaims late tracks, streams, timers, listeners, replies, and peer connections.
- Required browser/TURN/Safari gates fail on absent infrastructure; they never pass by skipping.
- Do not add mute, hold, DTMF, auto-recovery, multiple calls, video, data channels, PBX certification, or Node media.
- End every task with focused verification and a review-sized commit.
