# v0.3 Package Separation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publishable `@sip-worker/core`, browser-first `sip-worker`, and optional `@sip-worker/node` 0.3.0 workspaces with preserved signaling behavior, shared class identity, dual ESM/CommonJS output, and enforced browser isolation.

**Architecture:** Convert the repository root into a private npm-workspace orchestrator. Physically move environment-neutral code into core and concrete adapters into browser or Node, then enforce the one-way dependency graph with TypeScript projects, static audits, browser bundling, packed-consumer tests, and API reports. Package extraction is the only production change in this milestone.

**Tech Stack:** npm workspaces, TypeScript strict `NodeNext`, TypeScript project references, tsup, Vitest, esbuild browser audit, API Extractor 7.58.12, Node 20/22.

## Global Constraints

- Implement the approved [v0.3 package-separation design](../specs/2026-08-12-v0.3-package-separation-design.md) exactly.
- Package names and versions are `@sip-worker/core@0.3.0`, `sip-worker@0.3.0`, and `@sip-worker/node@0.3.0`.
- `sip-worker` and `@sip-worker/node` declare exact dependency `@sip-worker/core: "0.3.0"`.
- The root is private and is never packed or published.
- Retain ESM, CommonJS, `.d.ts`, `.d.cts`, and source-map output.
- Remove `sip-worker/transport/node`; do not add a compatibility shim.
- Preserve the current signaling behavior, stable error codes, and public class identity within ESM and within CommonJS.
- Core cannot import Node, DOM, WebSocket, Worker, timer, or crypto globals.
- Browser cannot import `node:*` or `@sip-worker/node`, and cannot read browser globals at import time.
- Node cannot import `sip-worker` or duplicate a core implementation.
- Production cross-workspace imports use package specifiers, never relative paths.
- Do not add WebRTC, browser reconnection policy, external SIP interoperability, or unrelated protocol changes.
- Move or update tests before deleting their old locations; never weaken an existing behavioral assertion.
- Every task ends in a focused verification gate and a review-sized commit.
