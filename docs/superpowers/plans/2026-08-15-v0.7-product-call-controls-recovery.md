# v0.7 Product Call Controls and Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the browser-first v0.7 internal-beta SDK with per-call ownership, bounded WSS/registration/call recovery, mute, hold/resume, RFC 4733 DTMF, refreshable TURN configuration, safe diagnostics, an example softphone, and reproducible browser evidence.

**Architecture:** Keep SIP and offer/answer truth in `@sip-worker/core`; put browser socket generations, reconnect policy, lifecycle integration, WebRTC controls, and the `BrowserPhone`/`BrowserCall` façade in `sip-worker`; leave `@sip-worker/node` separate. Build the milestone in dependency order and preserve v0.5 APIs as deprecated wrappers over the same owners, never as parallel state machines.

**Tech Stack:** TypeScript 5.5+, Vitest 2, Playwright 1.62, tsup, API Extractor, browser WebSocket, WebRTC `RTCPeerConnection`/`RTCDTMFSender`, existing injected `Clock`, coturn, macOS `safaridriver`, plain HTML/CSS example.

## Global Constraints

- Begin execution from commit `b0a10f7` in an isolated worktree created with the `using-git-worktrees` skill; suggested branch/worktree name: `worktree-v0.7-product-controls-recovery`.
- Use subagent-driven development: one fresh implementer per task, then specification review and code-quality review before the task commit is accepted.
- Follow strict TDD for every behavior: observe the focused test fail for the intended reason before production code, then make the smallest coherent change and rerun the focused and affected suites.
- Do not weaken, skip, quarantine, retry-away, or mark `continue-on-error` on any existing or new required gate.
- Core imports no DOM, WebRTC, browser lifecycle, WebSocket global, Node built-in, ambient timer, or ambient randomness at runtime.
- Browser public imports remain side-effect-free and access no browser global at import time.
- No new runtime dependency is permitted. Reuse TypeScript, Vitest, Playwright, esbuild, and repository test infrastructure.
- WSS is mandatory by default. `ws:` requires `allowInsecureWebSocket: true` and remains subject to browser mixed-content enforcement.
- One `BrowserPhone` owns at most one call. A second incoming call is answered 486 before media acquisition; a second outgoing call rejects `INVALID_STATE`.
- Complete non-trickle SDP remains the SIP compatibility policy. Do not add Trickle ICE.
- Default reconnect values are 250 ms initial delay, 5,000 ms maximum delay, eight total attempts, and 30,000 ms total recovery time. Validation caps are 20 attempts, 30,000 ms delay, and 120,000 ms recovery/operation time.
- Default public operation deadline is 30,000 ms; call establishment is 120,000 ms. A shorter SIP/media protocol deadline wins.
- Default hold offer direction is `sendonly`; `inactive` is the only alternative. Preserve the user's mute state through hold, resume, track replacement, ICE restart, and recovery.
- DTMF accepts only `0-9`, `A-D`, `*`, and `#`, uses negotiated RFC 4733 telephone events, and never falls back automatically to SIP INFO.
- Public errors, diagnostics, and docs never expose credentials, authorization headers, full SIP URIs, user headers, SDP, ICE candidates, IP addresses, device IDs/labels, or raw browser exception text.
- `dispose()` is idempotent, non-cancellable, locally bounded, and resolves only after every local owner/resource count reaches zero. Socket-close failure is diagnostic, not a cleanup leak.
- Shipping Safari is distinct from Playwright WebKit and remains a mandatory macOS release gate.
- v0.7 is an internal-beta/tightly-controlled-pilot release, not general customer-production certification.
- Preserve unrelated worktree changes. Stage exact task paths, never `git add .`.

- [ ] **Step 3: Implement the environment-neutral caller observer**

```ts
export interface OperationOptions {
  readonly signal?: AbortSignal;
  readonly timeoutMs?: number;
}

export const MAX_OPERATION_TIMEOUT_MS = 120_000;

export function validateOperationTimeout(value: number | undefined, fallback: number): number {
  const selected = value ?? fallback;
  if (!Number.isFinite(selected) || selected <= 0) {
    throw new RangeError('timeoutMs must be a finite positive number');
  }
  return Math.min(selected, MAX_OPERATION_TIMEOUT_MS);
}
```

The exact exported observer signature is:

```ts
interface ObserveOperationConfig {
  readonly clock: Clock;
  readonly operation: string;
  readonly defaultTimeoutMs: number;
  readonly options?: OperationOptions;
  readonly onAbort?: () => void | Promise<void>;
}

export function observeOperation<T>(
  source: Promise<T>,
  config: ObserveOperationConfig,
): Promise<T>;
```

`observeOperation` must attach one abort listener and one injected-clock timer,
reject the caller with a fixed safe `SipError`, detach both on first settlement,
and leave the source promise running so already-sent SIP work can reconcile.
Consume the source rejection internally even when abort/timeout wins, preventing
an unhandled rejection. It must never construct an ambient timer.

recover(): Promise<void> {
  if (this.recoveryPromise !== undefined) return this.recoveryPromise;

  this.reconnectPending = false;
