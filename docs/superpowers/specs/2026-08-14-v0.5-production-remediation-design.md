# v0.5 Production Remediation Design

**Date:** 2026-08-14  
**Status:** Approved  
**Scope:** Correct the production-readiness findings in the
`v0.5-real-webrtc-audio` implementation without redesigning unrelated SIP or
media architecture.

## Outcome

The v0.5 browser media foundation produces complete non-trickle SDP, bounds
every browser media operation, reports stable typed failures, completes ICE
restart signaling truthfully, and retains no per-call resources or identifiers
across an unbounded application lifetime. Test-only observability does not leak
through the published API.

This remediation preserves the existing split:

- core owns SIP, dialogs, media commands, correlation, and fallback deadlines;
- browser owns WebRTC, capture, devices, rendering, browser-operation deadlines,
  and concrete media resource cleanup;
- the structured-clone-safe media protocol remains the only boundary between
  those responsibilities.

## Configuration and Deadlines

`BrowserUserAgent` validates and normalizes `BrowserMediaOptions` exactly once
at construction. The normalized value is frozen and defensively copied before
being shared with browser media components. Copying includes nested
`RTCIceServer.urls` arrays and nested values accepted by
`MediaTrackConstraints`; later caller mutation cannot change active behavior.

`mediaOperationTimeoutMs` bounds browser-side offer creation, answer creation,
remote-description application, and ICE restart. When the deadline wins, the
manager:

1. invalidates the current operation generation;
2. closes the partial or active media session as appropriate;
3. releases late-arriving streams and tracks through existing session guards;
4. allows the serialized command queue to continue; and
5. replies with `MEDIA_OPERATION_TIMEOUT` using a safe, non-sensitive message.

The underlying browser promise is always observed after the race, so a late
resolve or rejection cannot become unhandled or mutate newer state.

`WorkerMediaController` receives the browser clock and a fallback deadline
strictly greater than the normalized browser operation deadline. The fallback
remains protection against a broken or lost bridge reply; normally the browser's
more precise `MEDIA_OPERATION_TIMEOUT` wins. Deadline arithmetic is capped and
must remain finite even when `mediaOperationTimeoutMs` is at its maximum.

## Complete Non-Trickle SDP

Offer, answer, and ICE-restart operations subscribe for ICE completion before
calling `setLocalDescription`, wait for bounded completion, and then read SDP
from `RTCPeerConnection.localDescription`. Returning the object originally
produced by `createOffer` or `createAnswer` is forbidden because it predates
candidate gathering.

After gathering, a missing, empty, or wrong-type local description fails with
`NEGOTIATION_FAILED`. Tests must make the fake peer connection append a distinct
candidate only to `localDescription` during gathering and assert the returned
offer, answer, and restart SDP contains it.

The ICE waiter is explicitly cancelled and awaited when
`setLocalDescription` rejects. No promise created by the operation may reject
without an observer.

## SIP Re-INVITE Correctness

For a successful response to an outgoing re-INVITE, the dialog negotiator sends
and awaits the ACK before reporting ICE restart success. ACK transport failure
rejects the restart with `TRANSPORT_FAILED`; applying the remote SDP cannot turn
a failed signaling exchange into success. The negotiator still terminates its
owned transaction exactly once.

Incoming re-INVITE answer generation keeps the synchronous busy claim. Both the
200 and 488 response paths use a safe response helper that contains teardown
races. The asynchronous chain always has a terminal rejection observer and
always releases the busy flag. No response-send race reaches
`unhandledrejection`.

## Devices and Cancellation

A selected microphone is requested with an exact `deviceId` constraint. If the
device disappears between enumeration and capture, the existing browser error
mapping reports `DEVICE_NOT_FOUND` or `CONSTRAINT_UNSATISFIED`; the browser may
not silently select another microphone.

The acquisition abort race removes local and external `AbortSignal` listeners
on every settlement path: success, capture rejection, local abort, external
abort, and already-aborted input. A late stream after abort is still stopped.
Listener cleanup is idempotent and does not suppress observation of the
underlying capture promise.

## Bounded Session Correlation

The media manager must reject or ignore stale commands without retaining every
historical session ID. Replace the lifetime-wide `consumedSessionIds` set with a
bounded ownership rule based on the sole reserved/active session plus operation
generation. Commands invalidated by close carry the generation captured when
queued and cannot create a session after that generation changes. Once no queued
or active work can reference an old ID, no historical ID remains stored.

Tests run substantially more call/close cycles than the previous lifecycle gate
and assert the manager's retained correlation state returns to a constant-sized
baseline after each cycle.

## Error and Public API Contract

Add these values to the canonical `MediaErrorCode` union and safe-message maps:

- `INVALID_STATE`: a valid operation cannot start in the current media or call
  state, including a second simultaneous call;
- `MEDIA_OPERATION_TIMEOUT`: the browser-side media operation exceeded its
  configured deadline.

Both codes cross the media bridge unchanged and reconstruct as `MediaError`.
Unknown external codes continue to map to `INTERNAL_ERROR`. No `as
MediaError['code']` escape hatch remains for known states.

`UserAgent.activeInvitationsFor` is test-only state and must not appear in the
published declaration or API report. Tests should assert incoming-call behavior
through public events and session state, or through a non-exported test helper;
production declarations must expose no invitation map.

The `sip-worker/media` entry remains public. Low-level browser media exports are
not expanded further during this remediation.

## Security and Privacy

Timeout, SDP, device, and transport failures retain the current redaction
contract. Errors and events never expose SDP, ICE candidates or addresses,
constraints, device identifiers, stacks, SIP credentials, or TURN credentials.
No new logging is added.

## Testing and Acceptance

Every correction follows red-green-refactor with a focused regression test that
is observed failing before production code changes. Acceptance requires:

1. offer, answer, and restart return candidate-bearing
   `localDescription.sdp`;
2. rejected `setLocalDescription` creates no unhandled rejection;
3. normalized options are used in production and remain unchanged after nested
   caller mutation;
4. browser media deadlines release resources, observe late completion, unblock
   the queue, and surface `MEDIA_OPERATION_TIMEOUT` before the controller
   fallback;
5. re-INVITE restart cannot succeed when ACK transmission fails;
6. incoming re-INVITE response races are contained and release negotiation
   ownership;
7. selected microphones use exact constraints;
8. abort listeners return to zero after every settlement path;
9. repeated call/close cycles retain no growing ID history;
10. `INVALID_STATE` and `MEDIA_OPERATION_TIMEOUT` survive protocol serialization
    and reconstruction;
11. generated API reports contain no `activeInvitationsFor`;
12. the full unit, type, architecture, API, bundle, packaging, and packed-consumer
    gates pass;
13. Chromium, Firefox, and WebKit direct/STUN/lifecycle media gates pass; and
14. forced TURN and real Safari remain mandatory explicit gates, never silent
    skips. If their required external environment is unavailable, the final
    report records them as unverified rather than passed.

## Non-Goals

- No multi-call support or general media-state-machine rewrite.
- No trickle ICE, video, data channels, screen sharing, or conferencing.
- No new persistence, logging, telemetry, or TURN credential service.
- No unrelated SIP refactoring or widening of package exports.
