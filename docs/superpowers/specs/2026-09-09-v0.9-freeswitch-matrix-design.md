# v0.9 Workstream 3a — FreeSWITCH Call Matrix Design

**Date:** 2026-09-09
**Status:** Draft for review
**Base:** Workstream 3 of the v0.9 interoperability design
([`2026-08-20-v0.9-interoperability-design.md`](2026-08-20-v0.9-interoperability-design.md#workstream-3--pbx-call-matrices))
and Milestone 5 of the browser v1.0 production roadmap.

## Purpose

Prove the supported call matrix of the **browser** `sip-worker` stack against a
real, self-contained, docker-provisioned FreeSWITCH — with two-way audio
verified programmatically rather than inferred from SIP traces. This is the
first half of the v0.9 "PBX call matrices" workstream; Asterisk is designed
and shipped separately once the FreeSWITCH harness is proven
(sequencing decision, 2026-09-09).

The gate closes when every matrix step passes in current Chromium and Firefox
against a pinned FreeSWITCH container, the recorded browser leg analyzes as
non-silent, and no required step can fail by skipping.

## Scope

### In scope

1. A committed, digest-pinned FreeSWITCH docker environment under
   `test/freeswitch-matrix/` — sofia profile with WSS/WebRTC configuration,
   digest auth on REGISTER, an echo dialplan with `record_session`.
2. A Playwright matrix harness whose page consumes the **packed**
   `@sip-worker/browser` artifact (never `packages/**/src`).
3. The supported call matrix exercised as real browser calls: registration,
   registration refresh, registration failure, outgoing call with two-way
   audio, incoming call, hold/resume, mute/unmute, DTMF (RFC 4733), remote
   BYE, and WSS-drop recovery.
4. Programmatic two-way audio proof: the browser sends a synthetic tone and
   measures received energy on the remote stream; FreeSWITCH
   `record_session` captures the browser leg and a node-side WAV RMS pass
   asserts non-silence.
5. CI: a nightly release gate (Chromium + Firefox, full matrix with audio
   proof) and a bounded PR slice (Chromium, audio-proof step excluded but
   every step it runs is fail-not-skip). Matches the `soak.yml` dual-trigger
   pattern.
6. Two structural integrity gates alongside: a packed-boundary gate (no
   `packages/**/src` imports from the harness) and a fail-not-skip integrity
   check that every declared scenario has its spec and test files.

### Out of scope

- **Asterisk** — separate spec and plan, after this harness is proven.
- **SIP INFO DTMF fallback** — excluded by the 0.7 review; DTMF is RFC 4733
  only (`sendDtmf`).
- **NAT shapes** (direct/STUN/TURN legs beyond what the runner provides),
  **previous-stable engines, Safari** — Workstream 4. Safari additionally has
  no docker-PBX leg because macOS runners are not docker-PBX hosts; this
  matrix targets Chromium + Firefox (decision, 2026-09-09).
- **Multi-tab ownership, predictive metadata, load testing** — follow-on work
  from the pilot, not this workstream.
- **Anything that can report a successful skip** — a skip is a gate failure
  by definition.
- **No production interop claim.** Passing the matrix authorizes v0.9's
  release gate only, consistent with the roadmap's certification rules.

## Locked decisions

1. **FreeSWITCH first, Asterisk later.** One PBX proven end-to-end before the
   second PBX is designed (decision, 2026-09-09).
2. **Engine scope: Chromium + Firefox.** The browser-media engine matrix
   minus WebKit. Firefox requires the PulseAudio null-sink provisioning
   already solved in `browser-media.yml`.
3. **CI topology: nightly gate + bounded PR slice.** The nightly job is the
   release gate (full matrix, audio proof); the PR job runs a bounded slice.
   Neither can skip.
4. **Driving surface: dedicated harness page** (`__runMatrixStep`), not the
   pilot's operator DOM. The browser-media `__runCallCycle` pattern is the
   precedent.
5. **Echo dialplan covers both audio directions.** `answer → echo` with
   `record_session`: PBX→browser energy is measured in-page on the remote
   stream, and browser→PBX non-silence is read off the recorded WAV. No
   media-file fixture leg.
6. **Two-way audio is proven by RTP recording + energy analysis** — verbatim
   locked decision 3 of the v0.9 interoperability design.
7. **Packed tarball boundary** — the harness page consumes freshly packed
   `@sip-worker/browser`, WS2's pattern.

## Architecture — per-run topology

Loopback only, ephemeral free ports, one container per run:

```
Playwright (Chromium | Firefox)
   │  https page (step-runner)          wss signaling            RTP
   ▼                                   ▼                          ▼
[harness page: packed @sip-worker/browser] ──► FreeSWITCH docker ──► record_session WAV
   │  __runMatrixStep(step, args)          --network host              │
   │   AnalyserNode energy / getStats       ports 8081 ws / 8082 wss    ▼
   └────────────────────────────────────────────────────► node-side rms.ts (non-silence pass)
```

- **FreeSWITCH container**: digest-pinned public image (exact registry/tag
  verified empirically at plan time — the WS2 rule: the spec's first-choice
  image is verified before the plan pins it; a registry "denied" fallback is
  recorded, never a silent swap). Runs with `--network host`; SIP and RTP
  ranges are pinned in the committed config so a host-run container is
  deterministic. Global-setup health-probes the container before any step.
- **Config**: committed under `test/freeswitch-matrix/fs-conf/` — minimal
  sofia profile exposing ws (8081) and wss (8082), one extension running the
  echo+record dialplan, `record_session` writing to the mounted volume,
  digest auth on REGISTER. No secrets in the config; credentials are
  per-run harness inputs.
- **TLS**: per-run minted local CA + leaf (bounded openssl pattern from
  `test/freeswitch-pilot/server.mjs`), certs mounted into the container for
  wss, CA trusted by the Playwright browser context. Certificates are
  ephemeral and never committed.
- **Ports and deadlines**: free ports picked before the container starts; the
  page server (HTTPS) serves the harness page and step assets. Every
  container/step wait is deadline-bounded; a timeout is a step failure.

## Components

```
test/freeswitch-matrix/
  fs-conf/                 committed FreeSWITCH config (sofia profile, dialplan, acl)
  index.html + page.ts     harness page: boots packed @sip-worker/browser, exposes __runMatrixStep
  server.mjs               HTTPS page server + per-run TLS minting (pilot-server pattern)
  harness.ts               page-side: matrix step runner, synthetic tone source,
                           AnalyserNode energy sampler, getStats sampler, event trace
  steps.spec.ts            Playwright: one test per matrix step, drives __runMatrixStep
  rms.ts                   node-side PCM16 WAV reader + windowed RMS energy pass
  rms.unit.test.ts         unit tests for rms.ts on synthetic WAV fixtures (vitest, no docker)
  config.unit.test.ts      unit tests for the config/credential surface (no docker)
  pack-workspaces.mjs      WS2's packer reused — harness consumes packed tarballs
  README.md                run idioms and the fail-not-skip contract
```

The `rms.ts` RMS pass is a pure function over WAV bytes — unit-tested with
synthetic PCM fixtures (silence vs tone), requiring no audio device, no
docker, no browser. `steps.spec.ts` asserts per-step structured results
`{ok, detail, traceEvents}` returned from the page; every in-page wait is
bounded and a timeout surfaces as a step failure, never a hang.

## The call matrix

Ten steps, each a Playwright test against the harness page. A missing step,
missing fixture, container failure, or assertion failure is a job failure.

| # | Step | Assertion core |
|---|---|---|
| 1 | register (digest 401→200) | `registrationState=registered`; identity call-id/cseq populated |
| 2 | registration refresh | re-REGISTER before expiry; ≥2 wire REGISTERs, no error records |
| 3 | registration failure (wrong password) | typed `REGISTRATION_FAILED` (final non-2xx, not a 2nd-401 auth-budget path) |
| 4 | outgoing call + two-way audio | call `confirmed`; page energy above floor on remote stream; recorded WAV RMS above floor |
| 5 | incoming call (FS `originate` to the registered extension) | `incomingCall` event; answer; `confirmed`; clean hangup |
| 6 | hold/resume | call state hold/resume transitions; RTP counters increase both ways after resume (getStats) — no AnalyserNode floor here; step 4 alone carries the tone/energy proof |
| 7 | mute/unmute | outbound track `enabled` flips; documented RTP behavior asserted via getStats |
| 8 | DTMF (`sendDtmf`, RFC 4733) | digits observable at FreeSWITCH (fs_cli log / dialplan capture) |
| 9 | remote BYE (FS hangs up) | call `terminated` from remote; clean event path; no error records |
| 10 | WSS-drop recovery | WSS transport severed during an established call; recovery diagnostic emitted; UA re-registers over the restored socket and the call re-establishes or fails cleanly with a typed code — asserts the documented recovery contract |

Step 4 is the release-proof step; steps 1–3 reuse WS2 scenario semantics
through the *browser* stack; the rest prove the control plane.

## Two-way audio proof

- **Browser → PBX**: the page starts a synthetic oscillator
  (`AudioContext` → `MediaStreamDestination`, a fixed tone) on the call. The
  dialplan runs `record_session` on the answered leg; the node-side RMS pass
  reads the WAV (PCM16) and asserts a windowed RMS above a per-run calibrated
  silence floor. Calibration records a known-length silence segment first so
  the floor reflects the run's own noise, not a hardcoded constant.
- **PBX → browser**: the echo dialplan returns browser audio; the page
  `AnalyserNode` over the remote stream measures energy over a bounded
  window, and getStats packet/byte counters strictly increase. This side
  requires the Firefox PulseAudio null sink — provisioning copied from
  `browser-media.yml`.
- Both directions must pass; a one-way result is a failure.

## Determinism and error handling

- Free ports chosen before the container starts; deterministic sofia profile
  (loopback, conservative timers, no aggressive-nat settings).
- Deadline-bounded container start (health probe) and every step wait;
  recording flushed before the WAV is read; a WAV that is absent or too short
  throws.
- No audio device, image pull failure, missing config file, or failed health
  probe is a hard failure. Fail-not-skip is structural: global-setup throws,
  and no step is conditionally skipped.
- Artifacts for diagnosis on `always()`: `record_session` WAVs, FreeSWITCH
  logs (fs_cli), Playwright traces, page console.
- The pilot's redaction rules apply: matrix artifacts contain no secrets and
  no disallowed raw protocol/media material.

## CI structure

New workflow **`freeswitch-matrix.yml`**, dual-trigger after `soak.yml`:

| Job | Trigger | Scope |
| --- | --- | --- |
| `freeswitch-matrix-pr` | PR | Chromium; steps 1–3, 5–10 (audio-proof step 4 excluded); bounded ~8–10 min; fail-not-skip on everything it runs |
| `freeswitch-matrix-nightly` | nightly + `workflow_dispatch` | Chromium and Firefox; all ten steps incl. recording proof; the v0.9 release gate |

Both jobs: ubuntu runner → PulseAudio null-sink provisioning (Firefox) →
mint TLS → start docker FreeSWITCH with health probe → run the matrix →
upload WAVs/FS logs/traces on `always()`. Failure = failed job, never a
skipped run. `npm audit`/toolchain and docs cleanup remain Workstream 5.

## Local runnability

- `npm run test:matrix:unit` — `rms.ts`, config surface, step-runner types;
  green with no docker, no browser, no audio device.
- `npm run test:matrix` — full local run against docker FreeSWITCH (Chromium).
- `npm run test:matrix -- <step>` — run one matrix step by name.

## Acceptance criteria

1. `npm run test:matrix` runs all ten steps against docker FreeSWITCH and
   exits 0.
2. The nightly workflow (Chromium + Firefox) is green on all ten steps and
   the recorded WAV asserts non-silent; the PR slice is green and bounded.
3. Each step is independently runnable by name; missing step or fixture fails
   CI (fail-not-skip is structural and integrity-checked).
4. The harness imports zero modules from `packages/**/src`.
5. Matrix unit tests pass without docker, a browser, or an audio device.
6. Artifacts redact cleanly: no secrets, no disallowed raw protocol/media
   material.
7. No unresolved critical or high-severity review finding remains.
8. The exact FreeSWITCH image digest, package hash, Git commit, and browser
   versions are attached to the run record.
