# v0.9 Interoperability and Operational Proof — Design

**Date:** 2026-08-20
**Status:** Draft for review
**Base:** The roadmap's Milestone 5
([`2026-08-12-browser-v1-production-roadmap-design.md`](../2026-08-12-browser-v1-production-roadmap-design.md#milestone-5--09x-interoperability-and-operational-proof))
and the remaining-v0.9 limitations recorded in
[`docs/reviews/2026-08-15-0.7-product-call-controls-recovery-review.md`](../../reviews/2026-08-15-0.7-product-call-controls-recovery-review.md).

## Purpose

Replace self-contained confidence with evidence from realistic systems. v0.9 is
closed only when the milestone gate passes: required CI jobs fail (never skip)
when infrastructure, scenarios, browser execution, or assertions are missing;
Asterisk and FreeSWITCH both pass the supported call matrix; two-way audio is
verified programmatically rather than judged from SIP traces; and the soak
completes without upward trends in timers, listeners, pending operations,
tracks, peer connections, or authentication state.

## Scope

### In scope

1. **Soak and observability** — a core-level soak and a browser-level soak,
   both with explicit resource ceilings (see Workstream 1).
2. **SIPp protocol corpus** — docker-provisioned SIPp scenarios covering the
   protocol/failure surface against `@sip-worker/node`.
3. **PBX call matrices** — versioned docker FreeSWITCH and Asterisk
   environments with WSS/WebRTC configuration, each passing a supported call
   matrix with programmatic two-way audio verification.
4. **NAT and browser matrix** — direct, STUN-assisted, and TURN-relayed media
   legs; current and previous stable Chrome, Edge, and Firefox plus current
   Safari on macOS.
5. **Docs and toolchain hygiene** — deployment, troubleshooting, security,
   migration, and operations guides consolidated from the existing partial
   documents; `npm audit` remediation; the five `ae-forgotten-export` warnings
   resolved or explicitly tracked.

### Out of scope

- **SIP INFO DTMF fallback** — explicitly excluded by the 0.7 review; DTMF is
  RFC 4733 only.
- **`@sip-worker/node` release readiness** — the node package keeps its own
  support table; its status does not alter browser `sip-worker` guarantees.
- **1.0.0 API freeze and RC period** — Milestone 6, not 0.9.
- **External interop legs that can skip** — any job that would report a
  successful skip violates the gate and is out of scope by definition. (The
  existing forced-TURN leg is in scope and is extended in Workstream 4.)

## Locked decisions

1. **Environments run in Docker in CI.** Versioned containers and
   configuration are committed in-repo; jobs always run and fail when broken.
   This is the only shape that satisfies fail-not-skip self-contained. (The
   previous-stable browser engines run on the existing hosted-browser runners,
   which are also CI-owned.)
2. **Soak is built at both layers.** A cheap continuous core soak plus a
   browser soak that closes the browser-level release gate (tracks and peer
   connections only exist at the browser layer).
3. **Two-way audio is proven by RTP recording + energy analysis.** The browser
   sends a synthetic audio source and measures received energy; the PBX
   records the browser leg (FreeSWITCH `record_session` / Asterisk `Monitor`)
   and the harness analyzes the recording for non-silence. Real RTP, no
   trace-gazing.

## Architecture — five workstreams

### Workstream 1 — Soak and observability

The browser side already owns the exact measurement surface the gate names:
`PhoneDiagnostics.resources()` returns an immutable `ResourceSnapshot`
([`docs/diagnostics.md`](../../diagnostics.md)) with `activeCalls`,
`pendingOperations`, `timers`, `peerConnections`, `localTracks`, listener
counters, and a zero-resources baseline asserted after `phone.dispose()`. The
core side has no public counter surface, so the core soak samples through
existing injection points rather than adding public API.

**Core soak** (`test/soak/core-soak`): a node process boots `TransactionLayer`
with `Registrar` and `Inviter`/`Invitation` loops on a real clock against a
deterministic fake peer (the `FakeTransport`-style harness with a real `Clock`
instead of `FakeClock`). A fixed cycle cadence runs registration, call
establishment, and teardown. After every cycle the harness samples:
scheduled-timer count (from the injected `Clock`), subscriber count (from
`TransactionLayer` subscribe/dispose), pending operations, and authentication
exchanges. A shared trend-assertion helper checks for no upward trend
(windowed median, linear-regression slope ≤ threshold, jitter-tolerant —
quantile-based, not raw-max) and asserts a zero-resource baseline after
teardown.

**Browser soak** (`test/soak/browser-soak.spec.ts`): Playwright + synthetic
audio. Repeated call cycles against the deterministic media endpoint
(equivalent to `test/freeswitch-pilot/relay.js` / the browser-media harness).
Periodic `phone.diagnostics.resources()` snapshots feed the same trend helper;
the dispose-baseline assertion is the existing zero-owned-resources contract.

Both layers share the trend-assertion helper, so a change to the measurement
model lands once.

### Workstream 2 — SIPp protocol corpus

A versioned SIPp image plus committed scenario files covering registration,
authentication, refresh, outgoing/incoming INVITE, CANCEL races,
retransmissions, BYE, malformed traffic, timeout, and reconnect behavior. The
corpus runs against the `@sip-worker/node` client in a mandatory CI job that
fails when a scenario or assertion is missing. No browser needed for the
protocol corpus. Whether the corpus targets the packed tarball or the workspace
build is decided in the Workstream 2 plan (packed, per the pilot's constraint,
is the default).

### Workstream 3 — PBX call matrices

Versioned docker images and committed WSS/WebRTC configuration for FreeSWITCH
and Asterisk (the FreeSWITCH pilot's runbook is the starting point for the
FreeSWITCH leg). A browser acceptance run against each PBX executes the
supported call matrix: registration, out/incoming calls, hold/resume,
mute, DTMF, remote BYE, recovery. Two-way audio is programmatically verified:
the browser sends a synthetic source and measures received energy; the PBX
records the browser leg and the harness analyzes the recording for
non-silence. The audio-sink provisioning already solved for the browser-media
CI applies to these jobs.

### Workstream 4 — NAT and browser matrix

Extend the existing coturn-based forced-TURN leg with direct and STUN-assisted
media legs so the matrix covers all three NAT shapes. Pin current and previous
stable Chrome, Edge, and Firefox plus current Safari on macOS in the browser
matrix (the three-engine and Safari workflows already exist and are green at
`057683c`; the work is pinning previous-stable engines and structuring the
matrix).

### Workstream 5 — Docs and toolchain hygiene

Consolidate the existing partial documentation (`browser-phone.md`,
`browser-media.md`, `diagnostics.md`, `media-errors.md`, migrations,
`SECURITY.md`) into the deployment, troubleshooting, security, migration, and
operations guides the roadmap requires before 1.0. Remediate the `npm audit`
findings (1 critical via the vitest/vite dev chain, 2 high, 3 moderate — all
dev-only) with a tracked toolchain bump. Resolve or explicitly track the five
`ae-forgotten-export` warnings (`WaitForConnectedOptions`, `WebRtcMediaManager`,
`MediaManagerClock`, `BrowserLifecycleHost`, `createMediaPortPair`) ahead of
the v1 API freeze.

## CI structure

| Workflow | Change |
| --- | --- |
| `interop.yml` | Rebuilt from skip-based to **docker-provisioned, fail-not-skip**. The skip-when-absent semantics are deleted entirely. |
| `soak.yml` (new) | Nightly 8-hour core + browser soak (the release gate) and a PR job running a bounded slice (~15 min, rapid cycles) with the same assertions. |
| `browser-media.yml` | Extended with direct/STUN NAT legs and the previous-stable engine rows. |
| `ci.yml` | Unchanged; the fast pull-request checks. |

All required jobs are mandatory for an RC. A missing external environment is a
failed release prerequisite, never a successful test result (roadmap testing
strategy, item 6).

## Error handling, determinism, and cost

- The nightly 8-hour run is the release gate; the PR slice bounds cost.
- Every `getStats` and energy measurement is bounded against intermittent
  hangs — the fixes from the browser-media CI history (`057683c`) carry over
  verbatim as harness constraints.
- Trend assertions tolerate scheduler jitter (windowed medians over raw max),
  and both soaks assert an explicit zero-resource baseline, so a leak reads as
  a rising slope or a non-zero baseline rather than a flaky count.
- Soak and interop jobs fail on infra, audio, or scenario failure. No job
  reports a successful skip.

## Acceptance criteria → gate mapping

| Milestone gate | Proved by |
| --- | --- |
| Required CI jobs fail (never skip) when infra/scenarios/browser/assertions are missing | CI structure; `interop.yml` rebuild; mandatory RC jobs |
| Asterisk and FreeSWITCH both pass the supported call matrix | Workstream 3 (docker PBX + acceptance) |
| Two-way audio programmatically verified, not judged by SIP traces | Workstream 3 energy analysis (PBX recording + browser received-energy) |
| Soak completes without upward trends in timers, listeners, pending ops, tracks, peer connections, auth state | Workstream 1 (core + browser soak, shared trend helper) |

## Implementation sequencing

The milestone executes in dependency order, each piece with its own
implementation plan per the roadmap's governance (a phase cannot be marked
complete while its gate is skipped):

1. **Soak + observability** (Workstream 1) — the first implementation plan;
   establishes the resource-ceiling measurement model and the shared trend
   helper every later leg reuses.
2. **SIPp corpus** (Workstream 2) — protocol evidence before any PBX.
3. **FreeSWITCH matrix** (Workstream 3, FreeSWITCH leg).
4. **Asterisk matrix** (Workstream 3, Asterisk leg).
5. **`interop.yml` rebuild** — fail-not-skip once 2–4 give it real jobs.
6. **NAT legs + browser matrix** (Workstream 4).
7. **Docs + toolchain hygiene** (Workstream 5).
