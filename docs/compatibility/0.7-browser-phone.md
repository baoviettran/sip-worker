# Compatibility note: 0.7 browser phone

This note records the compatibility surface of the v0.7 browser phone release
for consumers upgrading from 0.5 and for browser-engine tractability. It
accompanies the [0.5-to-0.7 migration guide](../migrations/0.5-to-0.7.md).

## Package surface

- `sip-worker` (browser) now exports the product root `BrowserPhone`, the
  per-call handles `BrowserCall`, `OutgoingBrowserCall`, `IncomingBrowserCall`,
  the phone/call event maps and options, the state unions
  (`ConnectionState`, `RegistrationState`, `CallState`, `CallSignalingState`,
  `HoldState`), the reconnect policy constants, the diagnostics facade
  (`PhoneDiagnostics`, `ResourceSnapshot`, `DiagnosticRecorder`), the
  `DiagnosticCode` union, and the `IceServerProvider` type. It still re-exports
  the core API, `BrowserWebSocketTransport`, and the v0.5 media facade.
- The v0.5 `BrowserUserAgent` remains exported as a **deprecated** wrapper over
  the same phone runtime. It compiles and runs unchanged, delegates to the same
  owners, and creates no second state machine. Its `invite()` settles on core
  confirm only.
- `@sip-worker/core/media` continues to export `MediaError`, `MEDIA_ERROR_CODES`,
  `MediaErrorCode`, and the controller/bridge protocol.
- The dependency pins are exact across the 0.7.0 line:
  `sip-worker@0.7.0 → @sip-worker/core@0.7.0`, `@sip-worker/node@0.7.0 →
  @sip-worker/core@0.7.0`; core has no dependencies.

## No-Node-polyfill guarantee (browser bundle)

The browser package continues to build with esbuild `platform: 'browser'` and
**no** alias/inject/fallback/polyfill configuration, and the emitted bundle
contains no Node runtime token. The v0.7 phone surface (`BrowserPhone`,
`BrowserCall`, recovery, diagnostics) is import-time side-effect free: it reads
no `navigator`, `RTCPeerConnection`, `window`, `globalThis`, or `WebSocket` at
module scope. Browser globals arrive only through the injected seams
(`factory`, `lifecycle`, `mediaEnvironment`). This is enforced by
`npm run test:bundle`.

## Shared core class identity

`sip-worker` and `@sip-worker/node` re-export `@sip-worker/core`. When all three
tarballs are installed together the shared core is deduplicated, so
`sip-worker.SipError === @sip-worker/core.SipError`, and media errors are real
`@sip-worker/core.MediaError` instances on both sides of the boundary. This is
enforced by `npm run test:package` and `npm run test:compatibility`.

## Browser-engine tractability

The v0.7 phone surface (lifecycle, call controls, recovery, resource baselines)
is exercised on Chromium, Firefox, and Playwright WebKit against the built and
packed tarball in `test/browser-phone`. Playwright WebKit is browser-engine
automation, not evidence from shipping Safari; the dedicated macOS Safari
workflow remains a mandatory macOS release gate. The forced-TURN relay cases
run only with provisioned coturn in CI. See
[docs/browser-phone.md](../browser-phone.md) for the exact seam and evidence.

## One live call per phone

A `BrowserPhone` owns at most one live call. A second outgoing call rejects
`INVALID_STATE` before any media is touched; a busy phone answers a second
incoming INVITE with **486 Busy Here**. Applications that need concurrent calls
should create one phone per call.
