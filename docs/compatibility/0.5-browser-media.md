# Compatibility note: 0.5 browser media

This note records the compatibility surface of the v0.5 real browser media
release for consumers upgrading from 0.3 and for browser-engine tractability.
It accompanies the [0.5 migration guide](../migrations/0.3-to-0.5.md).

## `Invitation.answer()`

`answer(localSdp: string)` was removed in favor of `answer()`. The core
invitation applies the remote SDP offer and creates the local answer through its
media controller, then sends `200 OK`. Incoming SDP is no longer an application
concern.

## Package surface

- `sip-worker` (browser) now exports `BrowserUserAgent`, `BrowserMedia`, the
  browser media types and options, and `restartIce()`. It still re-exports the
  core API and `BrowserWebSocketTransport`.
- `@sip-worker/core/media` exports `MediaError`, `MEDIA_ERROR_CODES`,
  `MediaErrorCode`, plus the existing controller/bridge protocol.
- The dependency pins are exact across the 0.5.0 line:
  `sip-worker@0.5.0 → @sip-worker/core@0.5.0`, `@sip-worker/node@0.5.0 →
  @sip-worker/core@0.5.0`; core has no dependencies.

## No-Node-polyfill guarantee (browser bundle)

The browser package continues to build with esbuild `platform: 'browser'` and
**no** alias/inject/fallback/polyfill configuration, and the emitted bundle
contains no Node runtime token. The v0.5 DOM-typed media surface is type-only and
introduces no `navigator`/`RTCPeerConnection`/`document` reads at module import;
the browser media environment is resolved lazily inside the `BrowserUserAgent`
constructor (or injected via `mediaEnvironment`). This is enforced by
`npm run test:bundle`.

## Shared core class identity

`sip-worker` and `@sip-worker/node` re-export `@sip-worker/core`. When all three
tarballs are installed together the shared core is deduplicated, so
`sip-worker.SipError === @sip-worker/core.SipError`, and media errors are real
`@sip-worker/core.MediaError` instances on both sides of the boundary. This is
enforced by `npm run test:package` and `npm run test:compatibility`.

## Browser-engine tractability

Real two-way WebRTC audio is exercised on Chromium, Firefox, and WebKit/Safari
against the built and packed tarball with a synthetic in-page peer (autoplay
handled per engine; no real OS microphone). Media capabilities and default
autoplay policy vary by engine; applications should gate remote-audio playback
behind a user gesture and feature-detect `setSinkId`.

## Limitations

0.5 is a real-media **foundation**, not completed v1: one active call (busy →
`486`), non-trickle ICE only, no DTMF / SIP INFO / RFC 2833 / MSRP, no automatic
device-unplug fallback, no SIPS, no interop evidence against production media
stacks. See [`docs/browser-media.md`](../../docs/browser-media.md) for the full
list.
