## Remaining Limitations

The following limitations are unchanged by this milestone and are stated
truthfully; the 0.2.0 review does not claim otherwise:

1. **Signaling-only.** `sip-worker` 0.2.0 is a signaling prototype only; it
   ships no real media adapter (no RTP/RTCP, no DTLS/SRTP) and its media handler
   is the `StubMainMediaHandler` returning a fixed SDP string.
2. **No real WebRTC audio.** There is no browser microphone/camera capture, no
   `RTCPeerConnection`-backed media, and no WebRTC audio path.
3. **No production WSS policy.** There is no native TLS/SIPS/WSS transport, no
   production WebSocket policy, and no certificate/authentication story; a real
   TLS and authenticated transport must be fronted externally.
4. **No Asterisk/FreeSWITCH interoperability evidence.** The smoke gate is a
   self-contained loopback; there is no cross-testing against Asterisk,
   Kamailio, FreeSWITCH, SIP.js, or SIPp.
5. **No production browser support claim.** The browser transport is exercised
   in tests but 0.2.0 does not claim production browser support; browser v1.0
   requires the real media, WSS, and interop work tracked in the
   [browser v1.0 production roadmap](../superpowers/specs/2026-08-12-browser-v1-production-roadmap-design.md).
