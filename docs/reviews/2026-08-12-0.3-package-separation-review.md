# 0.3.0 Package Separation Review

## Scope

This review covers Milestone 2 (the v0.3 package separation), the implementing
commits from the milestone plan base `0a082bd` through HEAD `85e26c4`, plus the
release-candidate clean-tree verification recorded here. It is a package-boundary
release only: it splits the single 0.2.0 `sip-worker` package into three
independently packable workspaces (`@sip-worker/core`, `sip-worker`,
`@sip-worker/node`) without changing SIP behavior. It contains no WebRTC
implementation, no reconnection policy change, and no production-readiness claim.

The diff under review (`git diff 0a082bd..HEAD --stat`) is 219 files, +7855/-1642.
A source-level scan of the diff for `WebRTC|reconnect|RTCPeerConnection|
getUserMedia|MediaStream|RTP|SRTP|DTLS` additions found only pre-existing
signaling behavior (reconnection bookkeeping in the registrar, deterministic
test SDP fixtures) and negative assertions ("does NOT add WebRTC"); no new
WebRTC or media feature was introduced. The root manifest is now `private: true`
and is never packed or published.

All verification numbers below come from actual command output captured on
2026-08-12 from the working tree at HEAD `85e26c4` plus the verify-order fix
documented in the defect section.

## Defect found and fixed by this review

A clean-tree `npm run verify` failed on the first run. The `import-safety`
subtest of `test:architecture` (and the relocated browser/node vitest suites)
resolve `@sip-worker/core` through its package exports, which point at
`./dist/`. The verify chain ordered `test:architecture` and `npm test` *before*
`npm run build`, so on a truly clean tree (no leftover `dist`) they failed with
`ERR_MODULE_NOT_FOUND` for `@sip-worker/core/dist/*`. Prior task runs only passed
because `dist` lingered from earlier builds — exactly the class of defect the
clean-tree gate exists to catch.

The import-safety test header itself documents "Required: the packages must be
built first (npm run build) so `dist` exists", and the plan's own Task-4 gate runs
`npm run build` before `npm run test:architecture`. The root `verify` script was
reordered to build before the dist-dependent gates:

```json
"verify": "npm run test:docs && npm run typecheck && npm run build && npm test && npm run test:architecture && npm run test:api && npm run test:bundle && npm run test:package && npm run test:compatibility"
```

After this fix, the clean-tree `npm run verify` (from a removed
`node_modules` + `packages/*/{dist,.types}` and `npm ci`) exited 0 with every
gate green. The first-run failure and the fixed run are both recorded in the
SDD ledger (`task-10-verify-fail.log`, `task-10-report.md`).

## Remaining Limitations

These are inherited, unchanged, and out of scope for this milestone:

- No WebRTC, microphone/device management, RTP/RTCP, DTLS, or SRTP. Media remains
  the stub `StubMainMediaHandler`; the media-worker bridge is unchanged.
- No browser reconnection, network-change, or page-lifecycle policy. The existing
  deterministic re-registration-on-reconnect behavior is preserved but is not a
  production recovery policy.
- No TLS/SIPS/WSS deployment policy. WebSocket transports require an injected
  socket; no TLS handshake policy is built in.
- No external SIP interoperability evidence (Asterisk, FreeSWITCH, Kamailio, SIPp,
  SIP.js). The smoke flows exercise deterministic signaling only.
- 0.3.0 is a signaling-only prototype, not production-ready for general
  deployment. See `SECURITY.md`.
